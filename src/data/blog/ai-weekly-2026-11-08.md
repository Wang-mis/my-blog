## 本周摘要

本周的消息看似分散：模型接口和开放权重继续增加，Agent 开始被做成可长期使用的空间，AI 进入硬件设计、化学与机器人研究，算力园区也开始讨论怎样在电网紧张时减少负荷。把它们放在一起看，变化不在于“模型能做什么”的单次展示，而在于系统是否能在真实流程中留下足以检查的依据。

这条主线有三个层面。第一，长期任务需要保存、纠正和重复评估状态；第二，专业任务需要让确定性的工具、制造审核或实验验证接住模型输出；第三，规模化部署开始面对工具调用费用、能源和外部安全测试等运行条件。以下事实均以发布方的一手资料为准；关于影响和趋势的判断是编辑分析，不替代独立评测或实际部署结果。

## 本周关键词

- **长期记忆**：跨会话保留、检索并核对的信息，不等同于重新训练模型。
- **结构化工具调用**：模型传递经过验证的路径和参数，由程序执行，而不是自由拼接命令。
- **可验证中间结果**：能被人或程序复查的状态、来源、计算结果和操作记录。
- **开放权重**：可下载并在本地或自有环境运行的模型参数；它不自动等于低成本部署或无条件商用。
- **需求响应**：在电网负荷紧张时按约定降低用电的安排，是否有效仍要看实际运行记录。

## 本周重要进展

### 1. 长期 Agent 从一次对话走向可维护的工作空间

Meta 为 Muse 推出可保留和继续修改的 spaces；Anthropic 则公开了 Agent 记忆的分层做法，把原始记录、记忆笔记、知识页面和每次会话预先加载的信息分开，并讨论在空闲时回看记录、纠正错误的处理方式。Google ADK 2.14.0 同时将多项运行与评估接口转为稳定，支持同一案例重复运行并汇总结果，且把技能脚本改为验证后的路径和结构化参数。

这些变化解决的是同一个实际问题：当助手下周还要继续处理旅行计划、项目看板或代码任务时，不能只依赖一段旧对话。持久界面给任务一个固定入口，记忆层为信息标注来源和置信状态，重复评估则让团队看到一次成功是否只是偶然。它们也没有消除风险：后台更新是否及时、旧信息怎样失效、记忆整理消耗多少算力，都仍需在具体产品中验证。

来源：[Meta Muse spaces 公告](https://about.fb.com/news/2026/11/introducing-spaces-customize-muse-app/)、[Anthropic：Agent 记忆的组成](https://www.anthropic.com/research/components-of-agent-memory)、[Google ADK 2.14.0 Release](https://github.com/google/adk-python/releases/tag/v2.14.0)。

### 2. 模型供给增加，但“能下载”和“能完成任务”需要分开判断

本周，LongCat-2.5 正式版进入 API；腾讯发布 Hy4 正式版，并披露视觉理解与电脑操作能力；百度公开 ERNIE 5.5 Flash Base 基础权重；PFN 发布可离线运行的 PLaMo 3 Translate 多种尺寸权重。它们分别面向接口接入、产品中的多模态操作、后续训练研究和本地翻译，开放方式、成熟度与许可条件并不相同。

这意味着选择模型时，问题从“参数或榜单谁更高”延伸到部署与验收：基础权重尚未经过对话后训练，不能直接当作成熟助手；本地部署仍需评估硬件、日志流向和许可；接口上线也需要用完整任务检查工具误用、重试和人工接手。模型可获得性提高了比较空间，却没有替代针对自身数据和流程的测试。

来源：[LongCat API 更新日志](https://longcat.chat/platform/docs/zh/ChangeLog.html)、[腾讯 Hy4 发布说明](https://en.prnasia.com/releases/apac/tencent-launches-hy4-joining-the-ranks-of-the-world-s-leading-open-source-ai-models-554689.shtml)、[百度 ERNIE 5.5 Flash Base](https://ernie.baidu.com/release/ernie-5-5-flash-base)、[PFN：PLaMo 3 Translate](https://www.preferred.jp/en/news/pr20261105)。

### 3. 专业工作流强调“模型编排，专业工具和人来验收”

OpenAI 展示了 AI 协助完成设备外壳、电路板和软件设计并制造小批量原型的试验；Google DeepMind 为 Antigravity 加入化学信息学技能，让语言模型组织检索与工作流，RDKit 等专业工具执行分子计算。腾讯还公开了蛋白质模型和分子模拟工具的权重、代码与测试条件；NVIDIA 与 Ai2 则分别提供交互式世界模拟模型和可控的机器人积木环境。

共同变化是，模型不再只输出一段文字，而是被放到有数据、计算程序和后续验证的链路中。工程案例仍要考虑制造公差和装配；化学候选仍须合成与实验验证；世界模型生成的观测是否能支撑机器人策略，也不能只由画面逼真程度决定。对使用者而言，最重要的不是把这些演示写成“自动完成专业工作”，而是保留输入、工具版本、中间结果与人工审核结论。

来源：[OpenAI：物理世界工程](https://openai.com/index/accelerating-engineering-for-the-physical-world/)、[Google DeepMind：化学信息学工作流](https://deepmind.google/blog/agentic-cheminformatics-with-google-antigravity/)、[腾讯 Hyra-results](https://github.com/Tencent-Hunyuan/Hyra-results)、[Ai2 ToyBlocks](https://huggingface.co/blog/allenai/toyblocks)。

### 4. 安全与质量检查正在从“给出答案”延伸到“证明、复现和修补”

OpenAI 披露了在受控环境中复现 Linux 内核漏洞、生成候选补丁并交由研究人员审核的研究；CWE-bench v2 把漏洞修复与原有功能保留放进同一程序化检查；Anthropic 的 FlashProve 探索为特定模型计算附上密码学证明，以检查结果是否来自约定权重。OpenAI 也调整了漏洞奖励，并宣布与安全公司 Hacktron 合作，重点关注系统与第三方服务的连接处。

这些进展的共同点是把“模型看起来做对了”拆成可以分别核对的问题：漏洞能否复现、补丁是否保持功能、后台是否确为约定模型、工具权限是否跨服务一致。边界同样明确：内核研究的候选补丁并不等于全部已被上游接受；公开基准不能替代新环境测试；FlashProve 仍是适用条件和证明开销受限的研究原型；合作公告也不是安全效果报告。

来源：[OpenAI：Linux 内核安全研究](https://openai.com/index/a-thousand-fewer-paths-to-root/)、[CWE-bench v2](https://huggingface.co/blog/cwe-bench)、[Anthropic FlashProve](https://www.anthropic.com/research/provable-inference)、[OpenAI 与 Hacktron 合作](https://openai.com/index/partnering-with-hacktron/)。

### 5. AI 的运行成本开始被拆到工具、平台和电网层面

DeepSeek 的搜索与网页抓取接口于 11 月 1 日起按成功请求计费；两项大模型训练与推理平台推荐性通信行业标准开始实施。OpenAI 则提出 Grid Protectors：为未来计算园区与电力公司约定在电网压力大时降低需求，其佐治亚州 Effingham 项目包含最高 1,000 兆瓦的需求响应安排，但园区仍在开发中。

这三类消息提醒团队，模型调用成本只是总成本的一部分。一个资料任务的搜索、抓取、重试和人工复核都应记录；平台标准可作为选型核对表的入口，而非合格证明；需求响应是未来运行安排，不能代替新增电源和输电建设。随着 Agent 更频繁地使用外部工具，成本与基础设施条件会直接影响“能否持续运行”。

来源：[DeepSeek Search & Fetch](https://api-docs.deepseek.com/guides/search/)、[全国标准信息公共服务平台：YD/T 7170—2026](https://std.samr.gov.cn/hb/search/stdHBDetailed?id=5A166B0E8BF42BDAE06397BE0A0A0423)、[YD/T 7171—2026](https://std.samr.gov.cn/hb/search/stdHBDetailed?id=5A166B0E8BF52BDAE06397BE0A0A0423)、[OpenAI Grid Protectors](https://openai.com/index/grid-protectors-program/)。

## 趋势判断

本周最清晰的变化是，评价 AI 的单位正在从一次回答逐渐变成一段可运行的流程。长期 Agent 需要知道信息从哪里来、何时更新、错了怎样纠正；专业场景需要让程序计算、制造审核或实验验证参与判断；安全和基础设施则要求把权限、修补、调用次数与电力安排留下记录。

这不意味着模型能力不再重要，而是能力越强、可操作范围越大，越需要把边界写进系统。短期内，能够提供可复查中间状态、失败处理和明确开放范围的产品，会比只展示单次结果更便于团队试用。这个判断是对本周材料的归纳，尚不能据此推出所有市场或产品都会按同一节奏变化。
