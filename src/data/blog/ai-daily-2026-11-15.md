## 导读

让 AI 帮忙改代码，通常要经过几个环节：选择适合任务的模型，允许工具访问必要文件，再把结果完整交给用户。任何一环出问题，都可能让“模型已经答对”变成“应用没有做好”。

本期关注这条工作链上的三处变化：华为云增加模型入口，Qwen Code 补充任务交付和权限判断，LiteLLM 修复多种接口之间的转换问题。

本期收录 3 项进展，引用 6 个主要一手来源；相关代码变更说明与媒体报道用于补充核验。报道范围为 Asia/Shanghai（北京时间）2026 年 11 月 15 日 00:00—23:59，日期依据见文末。“发生了什么”依据来源资料，“为什么重要”和“值得关注”为编辑分析；本文未调用模型、运行新版工具或独立复现性能结果。

## 今日要点

- 华为云 MaaS 模型即服务平台上线 openPangu-2.1-Pro，官方发行表列版本为 20261115，支持 512K 上下文，目前提供西南-贵阳一的预置服务。[来源：模型发布公告](https://support.huaweicloud.com/bulletin-maas/bulletin-maas-0001.html)
- Qwen Code 0.27.4 正式发布，增加飞书、企业微信的仅发送 Webhook 入口，并调整自动权限判断，强调危险操作需要对应的明确授权。[来源：正式发布说明](https://github.com/QwenLM/qwen-code/releases/tag/v0.27.4)
- LiteLLM 1.108.9 将流式答案保留、缓存标记传递等修复带入长期支持分支，降低应用在接口转换过程中丢失信息的风险。[来源：正式发布说明](https://github.com/BerriAI/litellm/releases/tag/v1.108.9)

## 重点进展

### openPangu-2.1-Pro 上线后，开发者能怎样接入？

**发生了什么**

华为云模型发布公告新增 openPangu-2.1-Pro 文本生成模型，版本为 20261115。发行表列出 512K 上下文，以及工具调用、前缀续写、前缀缓存和思维链能力；其中工具调用是让模型提出调用外部程序的请求，实际执行仍由应用负责。当前表中仅预置服务标为支持，公共池和专属池部署均标为不支持。[来源：发行记录与服务形态](https://support.huaweicloud.com/bulletin-maas/bulletin-maas-0001.html)

官方模型列表将鸿蒙应用开发、ArkTS 代码生成和昇腾算子生成列为重点方向，并称模型的 Agent、代码和吞吐能力有所提升。这是厂商对适用场景与效果的说明，本文没有独立验证。接入指南要求实名认证、配置访问授权、开通服务并获取接口密钥，且明确限定西南-贵阳一区域。[来源：模型定位](https://support.huaweicloud.com/model-list-maas/model_list_0001.html)、[接入指南](https://support.huaweicloud.com/bestpractice-maas/bestpractice_maas_0021_03.html)

11 月 15 日更新的官方价目列出，每百万词元的未命中缓存输入价格为 0.8 元，输出为 3.2 元，命中缓存的输入为 0.016 元，不支持忙闲时差异定价。词元（token）是模型处理内容的计量单位；缓存优惠只作用于实际命中的部分，不能当作所有输入的统一价格。[来源：文本生成模型计费](https://support.huaweicloud.com/price-maas/price-maas-0002.html)

**为什么重要**

例如，维护鸿蒙应用的团队，更需要知道生成的代码能否通过编译、是否符合平台接口，以及完成一次修改要花多少时间。针对特定语言和硬件生态的模型入口，为这类比较提供了一个可实际接入的选项。

评估时应把自己的构建、测试和人工检查纳入流程。托管接口上线说明可以通过云服务调用；若要自行部署，还需另行核对对应版本的权重、许可与运行条件，不能只依据 openPangu 的品牌名称作判断。

### Qwen Code 如何把任务结果交出去，并更清楚地判断权限？

**发生了什么**

Qwen Code 发布 0.27.4 正式版。发布说明列出飞书与企业微信的 Webhook 支持，即通过预先配置的群机器人地址发送结果；配套变更明确，这两种新增连接方式仅用于发送，不接收群消息。用户可把配置好的群选为定时任务的交付目标。[来源：版本说明](https://github.com/QwenLM/qwen-code/releases/tag/v0.27.4)、[飞书连接说明](https://github.com/QwenLM/qwen-code/pull/17013)、[企业微信连接说明](https://github.com/QwenLM/qwen-code/pull/17224)

自动权限模式也调整了判断依据：操作与用户目标相关，不足以证明用户已授权破坏性操作、丢弃工作或改写共享历史。维护者修改了权限分类器的提示要求，保留日常可恢复步骤的处理方式；这属于模型判断规则的改进，不能据此保证所有危险操作都会被识别。[来源：权限判断变更及评估边界](https://github.com/QwenLM/qwen-code/pull/16858)

版本还包含托管 Agent 会话访问用户授权本地目录的能力，但对应变更说明指出，部署开关默认关闭，还需要会话能力支持。临时授权信息不持久化，不代表工具返回的文件内容完全不留存：作为工具结果返回的内容，仍遵循会话原有的持久化规则。[来源：本地文件访问的启用条件与数据处理](https://github.com/QwenLM/qwen-code/pull/16844)

**为什么重要**

对于“检查项目并把报告发到团队群”这样的任务，工具需要同时解决结果送达和操作范围两个问题。群机器人让报告有固定去处，权限判断则需要区分“可以检查代码”和“可以删除分支”等不同授权。

这些改进有助于把编程助手接入日常工作，但配置好的发送通道不等于已验证消息成功到达，分类器也不能替代执行层的权限限制。团队仍应明确哪些目录可访问、哪些结果可发送，以及失败后由谁接手。

### LiteLLM 为什么要修复“答案算对了，却少显示一部分”？

**发生了什么**

LiteLLM 是帮助应用对接不同模型服务的接口适配工具。其 1.108.9 正式版把多项修复带入长期支持分支，包括 Responses 流式回答、缓存控制标记，以及部分云平台的请求格式处理。[来源：1.108.9 发布说明](https://github.com/BerriAI/litellm/releases/tag/v1.108.9)

其中一项修复针对混合数据片段：上游服务在同一片段里同时返回推理内容和答案开头时，原有转换可能丢掉第一个答案片段，造成逐段显示的文字与最终完整响应不同。补丁调整同步与异步处理，让推理与答案都被保留；维护者提供了回归测试和前后对比记录。[来源：流式答案保留修复](https://github.com/BerriAI/litellm/pull/51356)

另一项修复让聊天接口转为 Responses 请求时保留调用方指定的缓存控制标记。这有助于支持这些标记的下游服务使用缓存，但不意味着所有服务都支持相同缓存规则，也不保证每次调用命中缓存。[来源：缓存标记转换修复](https://github.com/BerriAI/litellm/pull/51796)

**为什么重要**

如果应用把模型输出逐段显示给用户，丢掉一个数字或词语就可能改变答案含义。这类错误发生在模型外部，单看模型评测分数难以发现。

维护多模型应用时，除了核对最终响应，还应比较流式显示、工具调用参数和缓存统计。长期支持版纳入这些修复，让仍在维护既有部署的团队可以针对相关路径验证升级效果，而不必把问题误判为模型能力不足。

## 值得关注

- **按业务任务验证模型。** 对鸿蒙或昇腾开发，编译结果、测试通过率和完整任务费用，比单独的上下文长度更能说明适用性。
- **分别检查权限与交付。** 允许读取目录、允许修改文件、允许向群发送结果，应有各自清楚的范围；后台任务完成后，还要确认结果确实送达。
- **把接口转换纳入回归检查。** 流式文本应与最终响应一致，工具参数和缓存标记也应在经过适配层后保持预期含义。
