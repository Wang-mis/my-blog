## 导读

让 AI 处理一份文件，常常会遇到比回答问题更具体的困难：助手能否访问正确的目录，几个任务同时提问时会不会答错对象，照片里的倒置文字怎样识别，工具返回太多内容后连接是否还能正常结束？这些环节决定了一项功能能不能持续使用。

今天的更新集中在这些实际问题上：Open WebUI 把能调用工具操作文件的本机编码助手（Agent）接入工作台，Qwen Code 改善多任务交互，Ultralytics 补齐从定位文字到读出内容的流程，LiteLLM 修复较大工具结果的传输故障。

本期收录 4 项进展，引用 6 个主要一手来源。报道范围为 Asia/Shanghai（北京时间）2026 年 11 月 8 日 00:00—23:59；正式发布时刻及归日依据见文末。“发生了什么”依据官方发布说明，“为什么重要”和“值得关注”为编辑分析；本文未实测产品或独立验证修复效果。

## 今日要点

- Open WebUI 0.13.1 接入本机编码 Agent，推出桌面连接工具 Tether，并改变附件读取及工具权限规则；同日晚发布的 0.13.2 修复局域网普通 HTTP 访问问题。[来源：0.13.1](https://github.com/open-webui/open-webui/releases/tag/v0.13.1)、[0.13.2](https://github.com/open-webui/open-webui/releases/tag/v0.13.2)
- Qwen Code 0.27.0 支持同时保留多个子任务的问题，区分各自的回答草稿与错误，并让用户在作答前进一步了解选项。[来源：官方 Release](https://github.com/QwenLM/qwen-code/releases/tag/v0.27.0)
- Ultralytics 8.4.205 新增场景文字识别流程，8.4.206 随后改善倒置文字的处理；自定义识别器不自动获得方向纠正。[来源：8.4.205](https://github.com/ultralytics/ultralytics/releases/tag/v8.4.205)、[8.4.206](https://github.com/ultralytics/ultralytics/releases/tag/v8.4.206)
- LiteLLM 1.108.3 长期支持版修复超过 1 MiB（约 105 万字节）的工具结果传输失败，以及部分模型服务请求和审核重复执行问题。[来源：官方 Release](https://github.com/BerriAI/litellm/releases/tag/v1.108.3)

## 重点进展

### 聊天工作台怎样连接到自己的电脑？

**发生了什么**

Open WebUI 发布 0.13.1：当连接的 Open Terminal 提供编码 Agent 时，Claude Code、Codex 和 Pi 等助手可以出现在模型选择器中，用户可在聊天中批准工具请求。新增的 Tether 桌面配套应用支持 macOS、Windows 和 Linux，通过向外建立连接，把自己的电脑接到工作台，供模型、编码助手和自动任务使用本机文件与工具。[来源：Open WebUI 0.13.1](https://github.com/open-webui/open-webui/releases/tag/v0.13.1)

该版本还加入默认关闭的 Auto 工具权限模式：审核模型判断调用是否可以直接执行，审核出错、超时或上下文过大时转为请求批准。审核会把工具、参数及最近几条消息发给配置的评分接口。附件也有默认行为变化：使用原生工具调用时不再自动预加载文件，不支持工具或未启用文件工具的模型，需要开启预加载才能读取附件。[来源：权限与附件变化](https://github.com/open-webui/open-webui/releases/tag/v0.13.1)

随后发布的 0.13.2 修复通过局域网或 Docker 普通 HTTP 地址打开聊天时，因标识符生成函数不可用而一直加载的问题，也修复相关评论和 Markdown 编辑故障。[来源：Open WebUI 0.13.2](https://github.com/open-webui/open-webui/releases/tag/v0.13.2)

**为什么重要**

当聊天入口能操作真实文件时，使用体验更连贯，但连接哪台电脑、使用哪个目录、哪些动作需要批准，也就成为产品的核心行为。自动审核依赖模型判断和外部评分接口，不能被理解为所有危险操作都会被拦下。

升级还需要关注兼容性。官方说明 0.13.1 包含数据库结构变化，多实例部署不支持滚动升级；附件默认行为改变，也可能让原本可读的文件在某些模型下不再进入上下文。这些条件应在迁移前核对。[来源：升级与兼容说明](https://github.com/open-webui/open-webui/releases/tag/v0.13.1)

### 几个子任务同时提问，怎样避免回答串线？

**发生了什么**

Qwen Code 发布 0.27.0，改善由后台服务管理的 Agent 会话：多个子任务可以同时保留待回答的问题，用户可按任意顺序作答，各自的草稿和错误状态分开保存。网页工作台新增询问详情的侧任务，用于解释待选选项，不直接替用户作答。[来源：Qwen Code 0.27.0](https://github.com/QwenLM/qwen-code/releases/tag/v0.27.0)

发布说明还列出本地非托管会话的文件变化通知，以及命令中断反馈修复：按 Esc 或 Ctrl+C 取消后，命令会标为已中断，并保留已经产生的部分输出。[来源：文件事件与取消行为](https://github.com/QwenLM/qwen-code/releases/tag/v0.27.0)

**为什么重要**

多个任务并行时，用户需要知道每个问题属于谁、尚有哪些回答未提交。把问题与草稿分别绑定到任务，能减少交互混淆；提供选项解释，也让用户在信息不足时仍能保留决定权。

中断状态同样影响判断：已经取消的命令若显示“完成”，后续任务可能把不完整结果当作成功。此次更新改善的是协调和反馈，不能据此推出子任务的代码或结论已经正确。

### 从照片中读出文字，需要补齐哪些步骤？

**发生了什么**

Ultralytics 发布 8.4.205，为光学字符识别（OCR，即把图像中的文字转成可处理文本）加入完整流程：先用 YOLO26-Text 等模型定位文字，再接 PaddleOCR 或自定义识别器，返回文字、置信度、原图中的多边形位置及阅读顺序。该版本还介绍场景文字检测数据集，包含 65,325 张图像、约 129 万个单词区域标注；这些是检测标注，不包含供识别训练使用的文字转录。[来源：Ultralytics 8.4.205](https://github.com/ultralytics/ultralytics/releases/tag/v8.4.205)

几小时后发布的 8.4.206 加入文字行方向分类：对可能倒置的裁剪区域尝试两个方向，保留识别置信度较高的结果。这一自动纠正适用于 PaddleOCR 路径，自定义识别器仍需自行处理方向；相应依赖要求为 PaddleOCR 3.7 及以上、PaddlePaddle 3.1 及以上。[来源：Ultralytics 8.4.206](https://github.com/ultralytics/ultralytics/releases/tag/v8.4.206)

**为什么重要**

识别招牌或票据，既要找到文字，也要把区域裁剪、方向处理、识别结果和阅读顺序连起来。统一这些步骤，可以减少应用开发者重复编写流程的工作。

不过，返回置信度并不等于内容一定正确，检测数据集的规模也不能直接代表文字识别准确率。实际使用仍要抽查小字、模糊图像、复杂排版和目标语言；方向纠正也有明确的后端适用范围。

### 工具返回内容变大，为什么会让 Agent 任务失败？

**发生了什么**

负责统一接入多家模型服务的 LiteLLM 发布 1.108.3 长期支持版（LTS）。它修复模型上下文协议（MCP，一种让助手连接外部工具的协议）中，工具结果超过 1 MiB 时出现流连接结束却没有收到响应的故障；发布说明称该问题自 1.103.0 起存在。[来源：LiteLLM 1.108.3](https://github.com/BerriAI/litellm/releases/tag/v1.108.3)

该版本同时修复 AWS Bedrock 部署在 `api_base` 为空字符串时请求失败，以及模型级响应后审核被重复执行、连带两次调用审核服务的问题。[来源：服务接入与审核修复](https://github.com/BerriAI/litellm/releases/tag/v1.108.3)

**为什么重要**

一次任务可能已经查到文件、获得完整工具结果，却在传输阶段失败。此时更换模型或反复改写提示词都未必有用，诊断需要查看错误出在工具执行、网关传输还是模型读取阶段。

重复审核也可能增加延迟与调用开销。这次更新针对明确的故障条件，不代表大型结果的传输、内存占用和模型上下文容量限制都已解决；部署者仍需用自己的典型结果大小验证。

## 值得关注

- **接入真实文件后，权限是否仍清楚？** 观察连接设备、工作目录和工具批准是否对应同一项任务，也要了解审核请求会发送哪些信息。
- **任务状态是否足以支持后续判断？** 中断、等待回答和成功完成应清楚区分；有部分输出不意味着任务已经完成。
- **验收能否覆盖完整流程？** 文字检测、文字识别、工具传输和模型读取各有边界。只看到单个组件运行成功，仍不足以判断最终任务可靠。
