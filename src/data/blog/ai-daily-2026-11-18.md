## 导读

让 AI 改一段代码、整理一份材料，使用者关心的不只是答案好不好，还包括完成任务的费用、可以使用的入口，以及执行记录能否核对。当工具开始登录网站、预约服务和付款，这些问题就更具体了。

11 月 18 日的进展沿着这条主线展开：OpenAI 更新通用模型，微软强调日常任务的成本与模型定制，Google 扩大个人助手的执行能力。企业监督和新闻来源合作，则涉及行动与信息怎样获得可信依据。

本期收录 5 项进展，引用 9 个主要一手来源。报道范围为 Asia/Shanghai（北京时间）2026 年 11 月 18 日 00:00—23:59，归日依据见文末。“发生了什么”依据来源资料，“为什么重要”和“值得关注”为编辑分析；本文未独立复现评测，也未实测这些服务。

## 今日要点

- OpenAI 发布 GPT-6.2 Astra 与 Sol，在 ChatGPT Work、Codex 和 API 提供入口；Astra 的标准输入、输出单价较 GPT-6 Astra 降低 20%。[来源：发布公告](https://openai.com/index/introducing-gpt-6-2-astra-sol/)
- 微软在 Ignite 发布 MAI 模型更新，Code 2 与 Code 2 Flash 已进入 GitHub Copilot；授权权重服务仍是后续交付安排。[来源：编码模型公告](https://microsoft.ai/news/introducing-mai-code-2-and-mai-code-2-flash/)、[授权权重说明](https://microsoft.ai/news/introducing-mai-licensed-weights/)

- 微软与 40 多家组织推动 AI Transparency Initiative，计划建立跨模型、跨供应商的透明度与独立核验标准。[来源：联合倡议公告](https://news.microsoft.com/source/2026/11/17/microsoft-and-organizations-across-industries-launch-ai-transparency-initiative-to-strengthen-enterprise-trust-in-ai-models-and-agents/)

## 重点进展

### GPT-6.2 的更新怎样影响任务费用与接入？

**发生了什么**

OpenAI 推出面向复杂项目的 GPT-6.2 Astra 和面向日常工作的 GPT-6.2 Sol。公告确认两者向 ChatGPT Work 与 Codex 的 Plus、Pro、Enterprise、Edu 用户提供，开发者可通过 API 调用。官方称其在专业文档、编码和计算机操作等任务中提高结果质量并减少输出用量，这属于厂商评测与产品定位。[来源：发布与开放范围](https://openai.com/index/introducing-gpt-6-2-astra-sol/)

在标准处理、输入不超过 272K 词元的档位，Astra 每百万词元输入、缓存命中输入、输出分别为 8、0.40、40 美元；Sol 分别为 2、0.10、10 美元。词元（token）是模型处理和计费的内容单位。两款模型的输入超过 272K 时，整次请求的输入与缓存费率翻倍、输出费率变为 1.5 倍，不能把短上下文单价套到所有长文档任务。[来源：Astra 规格与价格](https://developers.openai.com/api/docs/models/gpt-6.2-astra)、[Sol 规格与价格](https://developers.openai.com/api/docs/models/gpt-6.2-sol)

两者接受文字和图像、输出文字，支持 105 万词元上下文，最大输入为 92.2 万、最大输出为 12.8 万词元；上下文总量与最大输入量需要区分。模型支持的工具还需由相应接口提供，不能仅凭模型名称推断应用已具备全部执行能力。[来源：Astra 模型文档](https://developers.openai.com/api/docs/models/gpt-6.2-astra)、[Sol 模型文档](https://developers.openai.com/api/docs/models/gpt-6.2-sol)

**为什么重要**

单价下降给高频任务提供了重新比较的理由，但一次合格交付的费用还取决于输出长度、重试和人工修改。固定一组真实任务，同时记录质量、耗时与总账单，比直接套用基准中的成本比例更有用。

接入长文档应用时，也应同时检查输入上限和长上下文加价条件。能够放进更多材料，不意味着在同一费率下就能完成更多工作。

### 微软怎样把模型更新落到日常编码任务？

**发生了什么**

微软在 Ignite 公布覆盖编码、安全、图像、语音和决策等方向的 MAI 更新。对于开发者，最直接的入口是已在 GitHub Copilot 提供的 MAI Code 2 和 Code 2 Flash；后者同时进入 Microsoft Foundry 的有限访问预览。OpenRouter 等其他平台仍列为后续上线安排。[来源：模型更新总览](https://microsoft.ai/news/microsoft-ignite-2026/)、[编码模型开放状态](https://microsoft.ai/news/introducing-mai-code-2-and-mai-code-2-flash/)

微软称，Code 2 在四项日常编码基准的平均表现达到 GPT-6.1 Sol 的 98%，成本约为其 40%。公告脚注明确，部分评测使用微软内部平台，Code 2 的成本采用五折促销价；这一比较不代表所有项目的完成率或长期费用。官方也说明，这些编码模型尚未针对基础科学研究与特别长程的 Agent 工作进行调优。[来源：评测条件与适用范围](https://microsoft.ai/news/introducing-mai-code-2-and-mai-code-2-flash/)

微软另宣布 MAI Licensed Weights，让企业能够在自己的 Azure 环境部署和定制模型，并控制访问与升级。专门说明页的状态是“即将通过 Frontier Company 合作提供”，需要联系客户团队；这不能写成人人都能下载的开放权重发布。[来源：授权权重服务与交付状态](https://microsoft.ai/news/introducing-mai-licensed-weights/)

**为什么重要**

解释代码、修复局部问题和跨文件实现功能，所需能力与预算并不相同。按照实际任务选择模型，可能比所有请求统一使用最高价模型更合适，但仍需用维护者愿意合并的结果衡量收益。

授权权重服务则涉及另一种需求：企业希望掌握模型版本和适配过程。是否可用、能运行在哪里、采用什么许可，需要分别核对，不能仅用“可定制”判断部署自由度。

### Gemini Tasks 扩大开放后，用户可以交出哪些工作？

**发生了什么**

Google 宣布基于 Gemini 4 Hydrogen 免费推送 Tasks 更新，覆盖美国、日本、韩国、加拿大、澳大利亚和印度；高级功能首先在美国推出。官方展示的任务包括拨打商家电话预约、分析账单、管理日程与购物，用户可在 Gemini 中切换到 Task 入口。这里报道的是扩大开放与新功能，不是 Gemini 执行任务能力首次出现。[来源：更新公告与入口](https://blog.google/innovation-and-ai/products/gemini-app/tasks-in-gemini-free-new-features/)

按 Google 的说明，付款前会请求确认或预先授权，用户可设置支出上限；任务在专属的硬件隔离虚拟机中执行，并配合网页内容检查等防护。电话功能在部分美国州尚不可用，短信入口也要求美国号码和符合条件的运营商。Google 同时承认任务仍可能失败，有些网站需要用户接手完成最后一步。[来源：执行条件与限制](https://blog.google/innovation-and-ai/products/gemini-app/tasks-in-gemini-free-new-features/)

**为什么重要**

个人助手的价值开始体现在把多个小步骤连起来。预约服务需要找到商家、沟通时间、检查日历并写入结果，任何一步出错都可能影响最终安排。

权限设置应与任务一起考虑：允许读取账单、登录账户和完成付款，是不同程度的授权。使用者需要能查看过程、随时介入，并在任务结束后核对预约或收据，而不能只依赖助手的一句“已完成”。

### AI 透明度倡议准备解决什么监督问题？

**发生了什么**

微软与包括 Adobe、埃森哲、毕马威、Mastercard 和沃尔沃汽车在内的 40 多家组织推动 AI Transparency Initiative。计划包括参与美国国家标准与技术研究院（NIST）的相关 Agent 标准工作、共同制定开放标准，以及将成果引入 Microsoft AI、Foundry 和 Copilot；这是合作与实施方向，尚不是一套已经完成并通用的认证。[来源：倡议与实施安排](https://news.microsoft.com/source/2026/11/17/microsoft-and-organizations-across-industries-launch-ai-transparency-initiative-to-strengthen-enterprise-trust-in-ai-models-and-agents/)

公告强调，模型对自身行为的描述不能成为唯一证据。记录需要区分模型自述、执行环境记录，以及身份和权限系统等独立来源，让企业能够核实 Agent 接触了什么、采取了什么行动，以及获得过哪些授权。[来源：独立核验原则](https://news.microsoft.com/source/2026/11/17/microsoft-and-organizations-across-industries-launch-ai-transparency-initiative-to-strengthen-enterprise-trust-in-ai-models-and-agents/)

**为什么重要**

“为什么没有完成任务”常常需要从多个系统寻找答案。把身份、权限、工具调用和实际结果关联起来，可以帮助团队定位问题，也更容易判断一次操作是否越过授权范围。

这项倡议的实际价值，要看后续是否给出可实现的记录格式、互操作方式和可审查案例。参与组织数量本身不能证明系统已经安全，也不能替代企业自己的权限控制。

### 费加罗与 OpenAI 的合作怎样连接新闻原文？

**发生了什么**

费加罗集团与 OpenAI 宣布战略合作，范围包括《费加罗报》及相关刊物的当期报道和档案内容。公告称，这些内容将以摘要、节选和指向原文的链接在 ChatGPT 中被发现；费加罗保留编辑独立性和内容控制权。[来源：合作范围](https://openai.com/index/le-groupe-figaro-and-openai-announce-partnership/)

费加罗还计划在多个团队引入 ChatGPT Enterprise，并根据自身 AI 章程探索工作流程与读者服务。公告未给出所有内容接入的完成时间，也未披露完整商业条款，因此不能据此声称全部档案已上线或可以免费阅读全文。[来源：内部使用计划与公告内容](https://openai.com/index/le-groupe-figaro-and-openai-announce-partnership/)

**为什么重要**

新闻摘要只有保留原文入口，读者才方便检查上下文和报道依据。授权合作提供了一条内容进入助手的路径，实际体验仍取决于链接是否准确、信息是否及时，以及摘要能否保留必要限定条件。

对于内容机构，内部采用 AI 与把新闻授权给外部产品是两项不同安排。两者都值得跟踪，但计划部署不能当作已经取得效率收益的证据。

## 值得关注

- **把费用比较还原到具体条件。** 短上下文费率、促销价格和特定基准成本各有适用范围，预算应覆盖实际任务和优惠结束后的使用。
- **核对入口与交付状态。** 已进入产品、有限预览、需要商业合作和后续计划，对使用者意味着不同的等待与接入成本。
- **让执行与信息都有可核对的依据。** 任务需要操作记录和结果凭证，新闻需要原始链接；模型生成的总结只能作为检查的起点。
